# 診療材料新規採用申請システム

申請者（医師・看護師・コメディカル）が、病院に対して新たに導入したい診療材料の採用を申請するワークフローシステム。

## 💡 開発背景と目的
本システムは、現職（公務員）にて市立病院の財務課調達係に配属されていた際の実務経験をベースに作成した、Webアプリケーション（プロトタイプ）です。当時、1,000人規模の病院組織において「診療材料審査委員会」の事務局業務を担当し、実際に自ら発案し行った業務改革（既存品との価格比較によるプレゼン免除ルールの運用）を、もしシステムとしてデジタル化・自動化したらどうなるか、という着想から作りました。

* **実体験に基づくドメイン知識の活用:** 医療現場の多忙さや、申請者・メーカー・委員会それぞれのインセンティブを意識してルール設計しました。
* **業務効率化を提供するBtoB SaaSを想定:** 単なるCRUD操作の習得ではなく、BtoB SaaS領域で求められる「現場の課題を解決するロジック」と「品質担保（PlaywrightによるE2Eテスト）」を形にすることを目指しました。

## システム概要
本システムは、単なる申請手続きのデジタル化に留まらず、院内委員会における「プレゼンテーション免除基準」を申請画面に組み込んでいる点が最大の特徴です。既存材料との価格比較を厳格に行い、以下のようなインセンティブを働かせます。

* **メーカーへの価格交渉:** 「既存品との価格比較」を免除基準に設定。メーカーが安値を提示しなければ医師にプレゼン負担がかかる構造にすることで、自発的な最安値を引き出します。
* **院内採用品目数の抑制:** 安易な新規採用を防止し、類似品への集約を誘導。
* **委員会運用の効率化:** 基準を満たした良質な申請のプレゼンを免除し、審議時間を短縮。

## 主要機能（予定含む）
* **認証・認可:** Clerkを利用したアカウント制御
* **申請ワークフロー:** プレゼン免除基準（既存品との価格比較等）の判定ロジックを組み込んだ申請フォーム
* **データベース（Neon）:** 申請データ、ユーザープロフィール、診療材料マスタの管理
* **業者による代理入力（仕様検討中）:** 医師が多忙で申請手続きを行う余裕がない実務背景を考慮し、業者がアカウント登録を行って申請を代理入力できる権限・機能。

## 技術スタック
* **Frontend / Backend:** Next.js
* **Authentication:** Clerk
* **Database:** Neon (PostgreSQL) / Drizzle ORM
* **E2E Testing:** Playwright
