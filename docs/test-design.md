# 🧪 テスト設計思想 (Test Design)

JSTQB（ソフトウェアテスト資格）の知識をベースにしたテスト計画および自動テストの運用ルールについて記述します。

---

## 1. テスト観点と設計技法 (JSTQB)
* **同値分割・境界値分析:** フォーム入力（数量、文字数制限など）における正常系・異常系の洗い出し。
* **状態遷移テスト:** 申請ステータス（申請→承認/却下）のフロー検証。

## 2. E2Eテスト自動化方針 (Playwright)
* **配置ルール:** ディレクトリ集約スタイルを採用。ルート直下の `e2e/` ディレクトリ配下にテストファイル（`*.spec.ts`）を集約し、アプリケーションコードと明確に分離して管理します。
* **クリティカルパスの優先化:** ユーザーの主要な利用フロー（ログイン → 申請作成 → 承認）を最優先で自動化。
* **保守性の高め方:** Page Object Model (POM) デザインパターンの適用によるメンテナンス性の向上。

## 3. CI/CD パイプライン (GitHub Actions & Neon)
* **PRトリガーの自動実行:** Pull Request 作成・更新時に GitHub Actions で Playwright テストを自動実行。
* **DBアイソレーション（Neon Branching）:** PRごとに Neon の一時的な DB ブランチを自動生成・マイグレーションし、本番や共有環境を汚染しない安全な独立 E2E テスト環境で検証。
* **デバッグ・レポート:** テスト失敗時のスクリーンショットやトレースログ（Trace Viewer）を Artifact として自動保存。

## 4. 単体・コンポーネントテスト方針 (Vitest)
* **配置ルール:** コロケーション（Collocation）スタイルを採用。コンポーネントと同じディレクトリに `*.test.tsx`（例: `page.test.tsx`）を配置し、コードとテストの一体管理（保守性向上）を図ります。
