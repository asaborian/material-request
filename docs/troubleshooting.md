## 課題 1: 初期セットアップ完了後に画面が遷移せず「登録中...」で固まる
* **発生日:** 2026年8月23日
* **対象機能:** 新規ユーザー初期セットアップ機能 (`/setup`)
* **事象:**
  - `/setup` 画面で氏名・部署を入力して送信ボタンを押すと、DBへの登録（INSERT）自体は正常に完了するものの、画面が `/requests`（または `/`）へ遷移せず「登録中...」のままフリーズする。
  - DBには問題なくレコードが追加されているため、登録後の遷移ロジックに問題があると推測。

* **原因:**
  - **サーバーキャッシュの非破棄 (`revalidatePath` の欠落):** DB登録完了時 (`createUserAction`) に、サーバー側に残る `/` のキャッシュをクリアしていなかったため、`router.push('/')` で遷移した際に未登録状態の古い判定結果がそのまま参照されていた。

* **解決策:**
  1. **キャッシュの即時破棄 (`app/setup/actions.ts`):**
     Server Action 内の DB 登録処理直後に `revalidatePath('/')` を実行し、登録前の古い交通整理キャッシュを即座に消去。
  2. **【予防措置】動的評価の強制 (`app/page.tsx`):**
     交差点となる `/` ページにおいて、アクセスごとに確実に最新のDB・認証状態を評価させるため `export const dynamic = 'force-dynamic';` を付与。

* **💡 得られた知見・学び:**
  - Next.js App Router において、単に `router.push()` を呼ぶだけではサーバー側・クライアント側に保持された既存キャッシュを参照してしまい、状態変更後のリダイレクトが意図通り動かないリスクがある。
  - 「状態が切り替わるタイミングでの `revalidatePath`（過去の記憶の消去）」と、「評価ページの `force-dynamic`（今後の動的評価）」のセット運用が、認証・権限遷移の安定化に不可欠であると学んだ。

## 課題 2: SignUpButton 押下時のリダイレクト不具合とコンポーネント削除による回避
* **発生日:** 2026年8月23日
* **対象機能:** 認証機能（Clerk サインアップ動線）
* **事象:**
  - Clerkの `SignUpButton` を押下した際、意図したページへリダイレクトされず、遷移が途切れる（またはループする）問題が発生。

* **原因:**
  - ClerkのリダイレクトURLの指定の不具合による動作不良。

* **解決策:**
  - **コンポーネント自体の削除:** Clerk側の画面上にてサインアップに遷移可能なため、アプリ側でサインアップボタンを配置する必要性が低いと判断し、ボタン自体を画面から削除。

* **💡 得られた知見・学び:**
  - すべての不具合をコード修正で解決するだけでなく、「機能要件に対して本当に必要か」を検討し、不要な機能を削ぎ落として課題自体を回避（Scope out）することも有効な設計判断であると学んだ。
  - 将来的に個別のサインアップ動線が必要になった場合は、Clerkのルーティング設定（`afterSignUpUrl` 等）を再検証する。
